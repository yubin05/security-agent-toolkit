## 5교시 · 설정 파일이 고장 나도 거부하기

### 문제 5-1 · 설정 파일을 안전하게 읽는 함수 `load_json` 만들고, 고장 두 가지로 시험하기

- (가) 실행한 출력 전체를 붙여 넣고, 경고 두 줄이 각각 어떤 오류 때문에 나왔는지 적어 주세요.
  - 쓸 내용: ① 출력 전체 ② 경고 두 줄이 각각 어떤 오류 때문에 나왔는지
  - 답: 출력은 실제 실행 결과와 일치한다. 첫 경고는 users_typo.json이 없어 FileNotFoundError, 둘째는 users_broken.json의 마지막 항목 뒤 쉼표로 JSONDecodeError가 발생한 결과이며, 두 경우 모두 기본값 {}를 반환했다.

```text
config/users.json -> 사용자 6 명을 읽음, 판정을 계속한다
[경고] 설정 파일 없음: config/users_typo.json
config/users_typo.json -> 사용자 0 명, 등록된 사용자가 없다
[경고] 설정 파일 깨짐: config/users_broken.json
config/users_broken.json -> 사용자 0 명, 등록된 사용자가 없다
```

- (나) 🔍 실패했을 때 프로그램을 멈추지 않고 빈 설정을 리턴하는 것이, 오류로 멈추는 것보다 왜 안전한가요? 「멈춘 뒤 현장에서 생기는 일」을 넣어 적어 주세요.
  - 쓸 내용: ① 빈 설정을 리턴하는 이유 ② 멈춘 뒤 현장에서 생기는 일
  - 답: 빈 사용자 설정을 판정에 적용하면 등록 사용자가 없어 모두 거부하는 기본 거부를 유지할 수 있다. 단순 중단 후 업무를 재개하려고 판정을 끄거나 우회하는 상황을 피하려는 설계이며, 현재 시험은 빈 설정 반환까지만 확인했다.

- (다) 🔍 설정 파일이 깨져서 모두 거부되면 정산 업무가 멈춥니다. 운영자가 이 상황을 빨리 알고 복구하려면 판정 프로그램에 무엇을 더하겠습니까? 두 가지 이상 적고, 그중 가장 먼저 할 것을 고른 이유를 적어 주세요.
  - 쓸 내용: ① 더할 것 두 가지 이상 ② 가장 먼저 할 것과 그 이유
  - 답: 설정 오류의 경로·시각·종류를 로그에 남겨 담당자에게 알리고, 빈 설정으로 동작 중인지 보여주는 상태 표시와 검증된 정상 설정 백업·복구 절차를 추가하겠다. 먼저 알림을 적용해 업무 중단 원인을 빨리 파악하고 통제를 끄는 대신 복구하도록 한다.

## 6교시 · 테스트 케이스 설계

### 문제 6-1 · 꼭 지켜야 할 네 가지를 테스트로 설계하고, 팀원의 제안을 시험하기

- (가) `test_policy_extra.py` 를 실행한 출력 전체를 붙여 넣고, 실패한 줄 번호와 `AssertionError:` 뒤에 나온 글자를 적어 주세요.
  - 쓸 내용: ① `test_policy_extra.py` 출력 전체 ② 실패한 줄 번호 ③ `AssertionError:` 뒤의 글자
  - 답: 실패한 줄은 14번이며, 메시지는 「6. 만료 정각에도 허용되어야 한다(팀원 제안)」이다. 아래 출력은 실제 실행 결과와 일치한다.

```
5 통과
Traceback (most recent call last):
  File "G:\My Drive\security-agent-toolkit\access_control\test_policy_extra.py", line 14, in <module>
    assert ok == True, "6. 만료 정각에도 허용되어야 한다(팀원 제안)"
           ^^^^^^^^^^
AssertionError: 6. 만료 정각에도 허용되어야 한다(팀원 제안)
```

- (나) 🔍 그 실패는 코드가 틀렸다는 뜻인가요, 제안이 우리가 정한 만료 규칙과 다르다는 뜻인가요? 근거를 적어 주세요.
  - 쓸 내용: ① 코드가 틀렸는지, 제안이 정책과 다른지 ② 우리가 정한 만료 규칙과 3번 테스트 결과를 근거로 한 이유
  - 답: 코드 오류가 아니라 팀원 제안이 기존 정책과 다르다는 뜻이다. now < expires일 때만 허용하므로 17:59는 허용, 18:00은 거부가 맞으며, 기본 테스트 3번도 이 두 경계에서 통과했다.

- (다) 🔍 정책 코드를 바꿀 때마다 `test_policy.py` 의 1 ~ 4번 테스트를 돌리지 않으면 어떤 사고가 날 수 있나요? 네 개 중 하나를 골라, 그 테스트가 막아 주는 사고를 구체적인 장면으로 적어 주세요.
  - 쓸 내용: ① 고른 테스트 ② 그 테스트가 막아 주는 사고 장면
  - 답: 3번 만료 경계 테스트를 고르겠다. 예외 검사 조건을 실수로 <에서 <=로 바꾸면 18:00에 끝난 정산 조회 권한이 만료 정각에도 허용되는데, 이 테스트가 그 오류를 잡아 준다.
