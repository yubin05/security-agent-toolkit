## 찾아보고 알게 된 것

### 보안 담당자가 패킷을 직접 열어 보는 이유

보안 담당자가 패킷을 직접 열어 보는 이유는 실제 네트워크에서 어떤 통신이 오갔는지 확인하기 위해서다. 로그나 경고만으로 원인을 판단하기 어려울 때, 출발지·목적지 주소, 프로토콜, 포트, 통신 시점과 응답을 살펴보면 장애나 의심스러운 통신의 원인을 좁힐 수 있다. 예를 들어 연결 실패를 조사할 때 요청 이후 어떤 응답이 있었는지 확인하는 식이다.

Wireshark는 캡처한 패킷을 프로토콜별로 해석하고 필터링해 보여 주는 분석 도구다. 보안 문제 조사뿐 아니라 네트워크 장애 분석과 프로토콜 학습에도 사용한다. [Wireshark 공식 소개](https://www.wireshark.org/docs/wsug_html_chunked/ChapterIntroduction.html)

### 패킷은

패킷은 네트워크에서 데이터를 전달하는 단위다. IP 패킷을 예로 들면 출발지·목적지 IP 주소 같은 정보를 담은 헤더와 전달할 데이터를 담은 부분으로 구성된다. 데이터를 보내는 규칙과 주소 정보를 함께 담아 목적지까지 전달하는 단위라고 이해했다.

IP 패킷 안에는 TCP 세그먼트 등의 데이터가 들어갈 수 있다. IP 주소는 IP 헤더에, TCP·UDP 포트는 해당 전송 계층 헤더에 있으므로 모든 정보를 같은 헤더에 담는 것은 아니다. [RFC 791: Internet Protocol](https://www.rfc-editor.org/rfc/rfc791.html)

### Npcap은

Npcap은 Windows에서 네트워크 패킷을 캡처할 수 있도록 제공하는 드라이버와 라이브러리다. Wireshark가 패킷을 받아 분석하려면 캡처 기능이 필요하며, Windows에서는 Npcap이 이 역할을 한다. Wireshark는 분석 화면을 제공하고 Npcap은 패킷을 수집하는 기반을 제공한다고 이해했다. [Npcap 공식 가이드](https://npcap.com/guide/)

### `|` (파이프)는

파이프는 앞 명령의 출력을 뒤 명령의 입력으로 연결하는 기호다. 전체 결과를 직접 훑는 대신 다음 명령으로 필요한 내용을 걸러 낼 수 있다. PowerShell의 명령끼리는 텍스트뿐 아니라 객체도 전달할 수 있다. [PowerShell 파이프라인 공식 문서](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_pipelines)

수업의 Git Bash 예시:

```bash
tasklist | grep Code
```

`tasklist`로 실행 중인 프로세스 목록을 출력하고, `grep Code`로 `Code`가 포함된 줄만 남긴다. `grep`은 기본적으로 대소문자를 구분한다.

PowerShell에서 같은 목적의 명령을 사용하려면 다음처럼 적을 수 있다. `grep`은 PowerShell 기본 명령이 아니므로 터미널 환경을 구분해야 한다.

```powershell
tasklist | Select-String -Pattern 'Code' -CaseSensitive
```

`Select-String`은 기본적으로 대소문자를 구분하지 않으므로 수업의 `grep`과 같은 비교를 하려고 `-CaseSensitive`를 붙였다. [Select-String 공식 문서](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/select-string)
