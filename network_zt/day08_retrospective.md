# 2과목 회고 (2026-10-21)

## 잘 이해한 것

- Docker의 실행 상태·호스트 바인딩 주소·컨테이너 포트를 구분하고, 응답과 요청 로그를 대조해 노출 범위와 연결 오류를 판단할 수 있었다.
- JSON 정책 로그를 계정별로 연결해 10분 이내 거부 후 허용 후보를 찾고, 거부 이유별 건수를 집계했다.
- 같은 재시도 패턴도 기기 변경과 거부 이유에 따라 해석이 달라지며, 정상처럼 보이는 허용 기록도 앞뒤 맥락을 봐야 한다는 점을 이해했다.

## 막힌 것

- 6~8일 차: 로그의 이상 징후를 근거로 가설을 세우고, 도용 같은 결론을 어디까지 말할 수 있는지 구분하는 것이 어려웠다. 사실·가설·추가 확인 기록을 나눠 도식으로 정리했다.
- 8일 차: 404를 접근통제 결과로 해석했지만, 이번 로그는 없는 경로에 대한 응답이었다. 경로·시각·프로그램을 함께 보고 탐색 의심과 정상 favicon 요청을 구분했다.
- 8일 차: 빈 HostIp를 모든 주소 게시로 읽는 법과 컨테이너 root·호스트 root의 차이를 보완했다. 설정값 하나나 거부 건수만으로 원인을 확정하지 않기로 했다.
