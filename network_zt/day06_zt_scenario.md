# A사 Zero Trust 적용 방안

> 직원 12명 표본과 제시된 사고 기록을 바탕으로 작성한 도입 제안이다. 아래 통제는 적용 완료 상태가 아니다.

## 5대 원칙 적용 방안

- **ID:** 직원의 모든 접속 경로에 MFA를 적용하고, 퇴사·미등록 계정은 거부한다. 정산 배치는 서비스 계정 전용 인증을 사용하고 사람의 대화형 로그인을 금지한다.
- **Device:** 등록 기기와 계정의 연결 관계를 확인하고, 백신·패치 등 보안 점검을 통과한 기기만 접속시킨다. 미등록 기기의 새벽 정산 조회가 통과한 사례를 근거로 우선 적용한다.
- **Network:** 직원 PC·앱 서버·DB·배치 서버 구역을 분리하고 필요한 통신만 허용한다. 직원 PC의 DB 직접 연결은 차단하고 승인된 앱·배치 서버에서 필요한 DB 포트로만 연결한다.
- **Application:** 부서·서비스 계정별 허용 자원과 작업을 명시하고 목록 밖은 거부한다. 영업 계정의 정산 조회와 일반 직원의 계정 권한 변경을 제한한다.
- **Policy:** 새벽·해외 접속·MFA 미수행·대량 조회에 따라 추가확인 또는 거부한다. 요청별 점수뿐 아니라 계정별 일정 시간 내 조회 횟수·누적 건수도 확인한다.

## 판단과 집행

- **PDP(결정):** 중앙 정책 서비스에 둔다. 계정·등록 기기·자원별 역할/권한을 먼저 확인하고 위험 점수로 허용·추가확인·거부를 결정한다.
- **PEP(집행):** 정산 포털 앞의 인증 프록시/API 게이트웨이에 둔다. PDP 결과에 따라 앱 전달·추가 인증·차단을 집행하고 결과와 이유를 기록한다.
- 네트워크 방화벽으로 프록시 우회와 직원 PC의 DB 직접 연결을 제한한다. 프록시 인증 외에 앱에서도 자원·작업별 권한을 확인한다.
- 추가확인 시 원래 요청은 보류하고, 필요한 인증·기기 조치 결과를 반영해 PDP에 재평가를 요청한다. 확인에 성공했다는 이유만으로 자동 통과시키지 않는다.

## 흐름도

```text
사용자 --요청--> PEP(인증 프록시/API 게이트웨이)
                  |
                  +-- 계정·기기·자원·상황 정보 --> PDP
                                                  |
                        [필수 조건] 재직·등록 기기·자원 권한
                          실패: 거부 / 통과: 위험 점수 계산
                        [점수 기준: 학습용 제안]
                          정산 조회: >=50 거부 / >=20 추가확인 / 그 아래 허용
                          권한 변경: >=50 거부 / >=10 추가확인 / 그 아래 허용
                                                  |
                  PEP <------ 결정 + 이유 ----------+
                   |
                   +-- 허용 ------> 앱(자원·작업 권한 확인) --> 허용 자원
                   +-- 추가확인 --> 요청 보류·추가 인증/조치 --> PDP 재평가
                   +-- 거부 ------> 차단
                   +-- 각 결과 ---> 감사 로그
```

자원 권한·반복 조회 누적 검사는 도입 제안이며 현재 실습 코드에는 구현돼 있지 않다. 서비스 계정은 승인된 배치 작업·서버·시간·인증 정책으로 별도 평가한다.

## 최소권한 기준 (목록에 없으면 거부)

- **기본 거부:** 아래 허용 자원·작업 목록에 없는 요청은 점수가 낮아도 거부한다. 추가 업무는 권한 승인 후 허용 목록을 변경한다.
- **재무팀:** SETTLE 정산 내역 조회만 허용한다. 계정 권한 변경은 허용하지 않는다.
- **영업팀:** SALES 영업 실적 조회만 허용한다. SETTLE 정산 조회는 거부한다.
- **서비스 계정 batch-night:** 등록된 SRV-BATCH에서 승인된 02:00 SETTLE 집계 작업만 허용한다. 대화형 로그인·다른 자원 접근은 거부한다.
- **계정 관리자:** account_admin 역할에만 계정 권한 변경을 허용하고 강화된 기기·인증 정책을 적용한다. 다른 자원 권한은 자동으로 부여하지 않는다.

- **우선 개선: 기기 등록·보안 상태 검사.** 점검 통과가 3/12명이고, 미등록 기기로 정산 120건을 조회한 사례가 있어 우선 접속 조건을 강화한다.
- **병행 개선: MFA와 위험 기반 인증.** 비밀번호 유출 후 해외 로그인 시도 2건 중 1건이 성공한 기록을 근거로 접속 경로의 MFA 누락을 없애고 이상 상황에 추가 검증을 적용한다.
- **후속 개선:** 0점인 세그멘테이션을 적용하고, 영업팀의 정산 권한과 반복 조회 누적 통제를 정비한다. 도입 후 적용률·정상 업무 영향·차단 및 예외 기록을 재확인한다.
