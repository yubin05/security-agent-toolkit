### 문제 2-1 · 알림 A 확인 — 서버 두 대로 열려 있는지 재고, 설정 값 · 비밀번호 · 실행 사용자까지 점검하기

- (가) `docker ps` 의 `PORTS` 열에서 두 서버가 각각 어떻게 나왔는지 적어 주세요.
  - 쓸 내용: ① closed-web-8081 의 PORTS 값 ② open-web-8082 의 PORTS 값
  - 답: closed-web-8081: `127.0.0.1:8081->80/tcp` / open-web-8082: `0.0.0.0:8082->80/tcp, [::]:8082->80/tcp`
- (나) 🔍 `내주소` 로 접속했을 때 `closed-web-8081` 과 `open-web-8082` 의 결과(응답 번호)를 각각 적어 주세요.
  - 쓸 내용: ① closed-web-8081 의 응답 번호 ② open-web-8082 의 응답 번호
  - 답: closed-web-8081: `000` / open-web-8082: `200`. 000은 HTTP 응답 코드가 아니라 curl이 HTTP 응답을 받지 못했다는 표시이다.
- (다) 🔍 `closed-web-8081` 은 `127.0.0.1` 로 접속하면 열려 있는데 `내주소` 로는 거부되는 이유는 무엇인가요? 다른 PC가 접속하는 경우와 어떻게 같은가요?
  - 쓸 내용: ① 127.0.0.1 로는 열리는 이유 ② 내주소로는 거부되는 이유 ③ 다른 PC가 접속하는 경우와 같은 점
  - 답: closed-web-8081은 호스트의 루프백 주소 127.0.0.1에만 게시돼 해당 주소로는 접속되지만 LAN IP로는 접속되지 않는다. 다른 PC도 서버의 LAN IP를 대상으로 접속하므로 이 게시 포트를 이용할 수 없으며, 출발지 IP가 아니라 접속 대상 주소의 차이이다.
- (라) 🔍 사내 PC에서 접속되면 안 되는 관리용 서버를 켠다면 `-p` 를 어떻게 쓰고, 이것이 4일 차의 어떤 원칙과 같은가요?
  - 쓸 내용: ① -p 에 쓸 형태 ② 같은 생각을 말하는 4일 차 원칙
  - 답: `-p 127.0.0.1:8080:80`처럼 루프백에만 게시한다. 필요한 범위만 허용하고 나머지는 제한하는 방화벽 허용 목록·최소권한 원칙과 같은 생각이다.
- (마) 🔍 `docker inspect` 결과에서 두 서버의 `HostIp` 는 각각 무엇이고, `PORTS` 열의 어느 표시와 같은 뜻인가요?
  - 쓸 내용: ① closed-web-8081 의 HostIp ② open-web-8082 의 HostIp ③ 각각 `PORTS` 열의 어느 표시와 같은 뜻인지
  - 답: 실제 HostIp는 closed-web-8081이 `"127.0.0.1"`, open-web-8082가 `""`이다. 각각 PORTS의 `127.0.0.1:8081`(루프백 한정), `0.0.0.0:8082`·`[::]:8082`(모든 IPv4·IPv6 주소 게시)와 연결된다.
- (바) 🔍 `open-web-8082` 의 비밀번호가 `docker exec` 로 그대로 읽혔습니다. 왜 문제이고, 비밀번호를 환경변수에 넣을 때 어떻게 다뤄야 하나요?
  - 쓸 내용: ① 읽힌 값 ② 왜 문제인지 ③ 다룰 때 지킬 것 두 가지 이상
  - 답: 실습용 `DB_PASSWORD` 값이 환경변수로 평문 조회됐으며, Docker 관리 권한이 있는 사용자는 exec·inspect 등으로 이를 확인할 수 있다. 비밀번호를 코드·이미지·저장소·로그에 남기지 않고, 필요한 서비스에만 전달하며, 운영에서는 시크릿·비밀 관리 서비스를 사용한다.
- (사) 🔍 `whoami` 결과는 무엇이고, 이 서버가 침해되면 왜 위험이 커지나요? 6일 차 최소권한과 어떻게 이어지나요?
  - 쓸 내용: ① whoami 결과 ② 위험이 커지는 이유 ③ 최소권한과 이어지는 점
  - 답: whoami 결과는 `root`로, 침해 시 컨테이너 내부에서 넓은 권한으로 파일·설정을 바꿀 수 있어 피해가 커진다. 호스트 root 권한을 즉시 얻는다는 뜻은 아니며, 서버 프로세스는 필요한 권한만 가진 비루트 계정으로 실행해 최소권한을 적용한다.

- (나) 🔍 `probe-web-8087` 의 접속 기록은 장애 · 위협 · 접근통제 중 무엇인가요? 출처 · 시각 · 경로 · 프로그램 중 세 가지 이상을 근거로 적고, 10/19(월)의 `favicon.ico` `404` 와 무엇이 다른지 적어 주세요.
  - 쓸 내용: ① 유형 ② 근거 세 가지 이상 ③ `favicon.ico` 404 와의 차이
  - 답: 분류는 위협 의심(경로 탐색)이다. 같은 출처 `172.17.0.1`에서 `2026-10-21 03:10:46 UTC`에 `curl/8.21.0`으로 `/admin`·`/login`·`/.env`·`/wp-login.php`·`/backup.zip`을 연속 요청해 404, `/index.html`은 200이었다. favicon 404는 브라우저가 탭 아이콘을 요청했지만 파일이 없었던 경우이며, 이번 실습 기록도 실제 공격으로 확정할 수는 없다.
- (답장) 보안 담당에게 보낼 답장을 씁니다. A · B · C 마다 유형 · 확인한 근거 · 먼저 할 일을 적어 주세요.
  - 쓸 내용: A · B · C 마다 ① 유형 ② 확인한 근거(`PORTS` 값 · 응답 번호 · 기록 줄) ③ 먼저 할 일

    - A 접근통제: `0.0.0.0:8082->80/tcp`로 게시돼 LAN IP 접속이 200이었다. 관리용이라면 루프백으로 노출 범위를 줄이고, 평문 비밀번호 관리와 비루트 실행도 개선한다.

    - C 위협 의심: 같은 출처·같은 초에 curl로 관리·설정·백업 경로를 연속 요청했다. 이번에는 실습으로 재현한 기록이며, 실제 경보라면 승인된 점검인지와 연관 로그를 확인한 뒤 대응한다.
- 이 교시에서 새로 알게 된 것 하나를 적어 주세요.
  - 쓸 내용: 자유롭게
  - 답: Up은 요청 처리 성공을 보장하지 않고, 000·404도 원인을 바로 말해 주지 않는다는 점을 배웠다. 포트 연결·요청 로그·경로·시각·프로그램을 함께 봐야 장애와 탐색 의심을 구분할 수 있다는 점이 기억에 남는다.

### 문제 3-1 · 거부 직후 허용 찾고 이유별 막대그래프 그리기

- (가) 내가 채운 코드를 붙여 넣어 주세요.
  - 쓸 내용: `# ←` 네 곳에 채운 코드(`json.loads` · 거부 후 허용 · `last` 기억 · 막대 출력 한 줄)
  - 답:

```python
    line = json.loads(text)   # 1. 임시 값입니다. text 를 json.loads 로 딕셔너리로 바꾼 값으로 바꾼다   # ←

    # 2. user 가 last 에 있고, last[user][0] 이 "거부" 이고, line["decision"] 이 "허용" 이고, now - last[user][1] 이 10 이하이면 "[거부 후 허용]", user, line["time"], line["device"] 를 출력한다   # ←
    if user in last and last[user][0] == "거부" and line["decision"] == "허용" and now - last[user][1] <= 10:

    # 3. last[user] 에 (line["decision"], now) 를 기억한다   # ←
    last[user] = (line["decision"], now)

    # 4. reason, "#" 를 count 만큼 반복한 글자, count 를 출력한다   # ←
    print(reason, "#"*count, count)
```
