## 2교시 · IP 주소 · 사설과 공인

> IP 주소는 실습 당시 기록한 값이다.

### 문제 2-1 · 내 IP 를 2진수로

- (가) 두 번째 파일(`warmup_2_1b.py`, 내 IPv4 주소)의 출력 네 줄:

```text
192 11000000
168 10101000
200 11001000
60 00111100
```
- (나-1) `format(number, "08b")` 가 마디 하나의 10진수를 어떤 형태의 글자로 바꾸는지, 내 출력 한 줄을 예로 들어 설명하세요.
  - 답: 정수를 이진수 문자열로 바꾸고 8자리보다 짧으면 앞에 0을 채운다. 예: 60 → `00111100`.
- (나-2) `"08b"` 에서 `08` 을 빼고 `"b"` 만 쓰면 `10` 은 어떻게 출력되나요?
  - 답: `format(10, "b")`는 `1010`, `"08b"`는 `00001010`이다. `08`을 빼면 8자리 0 채움을 하지 않는다.
- (나-3) 마디마다 8자리로 맞춰 써야 하는 이유를 설명하세요.
  - 답: IPv4 한 마디가 8비트여서 비트 경계를 보여 주기 위해 8자리로 쓴다. 경우의 수는 `2**8 = 256`, 범위는 0~255다.
- (다-1) IPv4 주소가 32비트라는 것과 마디 하나가 `0` ~ `255` 사이의 값만 가진다는 것은 어떻게 이어지나요? 마디 수와 비트 수를 근거로 설명하세요.
  - 답: IPv4는 8비트 × 4마디 = 32비트다. 내 주소 `192.168.200.60`의 각 마디도 0~255를 나타낸다.
- (다-2) 32비트로 만들 수 있는 주소의 개수: 2**32 = 4,294,967,296개
- (다-3) 그 개수가 나오는 계산 과정을, 비트 한 자리에 들어갈 수 있는 값의 가짓수와 자리 수를 넣어 단계별로 설명하세요.
  - 답: 각 비트가 0·1 두 값이므로 32비트 조합은 2를 32번 곱한 `2**32 = 4,294,967,296`개다.
- (다-4) 이 수의 한계가 사설 IP 와 NAT 를 쓰게 된 것과 어떻게 이어지는지 설명하세요.
  - 답: 예약 용도를 제외하면 쓸 수 있는 공인 IPv4가 줄고 장비는 증가해 주소가 부족해졌다. 사설 IP를 NAT로 변환하고, PAT로 여러 장비가 공인 IP 하나를 공유해 사용량을 줄인다.

### 문제 2-2 · 내 주소는 사설일까 — 인터넷이 보는 내 주소

- (가) `ipconfig` 의 내 IPv4 주소 · `curl` 로 본 공인 IP: 192.168.200.60, 1.245.252.171
- (나-1) 🔍 내 IPv4 주소는 2.2 표의 어느 범위에 들어가며, 그래서 사설과 공인 가운데 무엇인가요? 범위의 시작 주소와 끝 주소를 근거로 판정하세요.
  - 답: `192.168.200.60`은 사설 범위 `192.168.0.0~192.168.255.255`에 포함되므로 사설 IP다.
- (나-2) `curl` 로 본 주소는 사설과 공인 가운데 무엇인가요? 2.2 표의 세 범위와 맞춰 본 근거를 들어 설명하세요.
  - 답: 기록한 `1.245.252.171`은 세 사설 범위 밖이며 인터넷에서 확인한 출발지이므로 이번 실습에서는 공인 IP다. 사설 범위 밖에도 예약·특수 주소는 있다.
- (나-3) 관제 로그의 출발지 주소가 `172.20.5.6` 과 `172.32.5.6` 이라면, 각각 내부망 장비와 외부 주소 가운데 무엇으로 먼저 분류해야 하나요? 2.2 표를 근거로 설명하세요.
  - 답: `172.20.5.6`은 사설 범위 `172.16.0.0~172.31.255.255` 안, `172.32.5.6`은 밖이라 각각 내부·외부 주소로 먼저 분류한다. 실제 소속은 회사 주소 배정 정보로 확인한다.
- (다-1) 외부 서버 로그에 남은 출발지 IP 만으로는 내부망의 어느 PC 인지 특정할 수 없는 이유를 NAT 의 동작으로 설명하세요.
  - 답: NAT/PAT 뒤에는 변환된 공인 IP가 남아 IP만으로 내부 PC를 특정하기 어렵다. 통신 시각과 변환 기록을 확인하고, 정적 NAT는 고정 매핑을 대조한다.
- (다-2) 정적 NAT 과 동적 NAT 은 사설 IP 와 공인 IP 를 연결하는 방식이 어떻게 다른가요?
  - 답: 정적 NAT는 고정 1:1, 동적 NAT는 풀에서 필요할 때 배정하는 임시 1:1 매핑이다. 여러 PC가 공인 IP 하나를 동시에 포트로 구별해 쓰는 것은 PAT다.
- (다-3) 사원 PC 여러 대가 인터넷을 쓸 때는 동적 NAT 을 쓰는 이유는 무엇인가요? 동적 NAT 환경에서 외부 로그의 공인 IP 로 PC 를 특정하려면 무엇을 함께 봐야 하는지와 이어서 설명하세요.
  - 답: 사원 PC는 고정 공인 IP가 필요하지 않아 동적 NAT로 주소를 재사용할 수 있으나 동시 사용은 풀 크기에 제한된다. 추적에는 시각·변환 기록을, PAT라면 IP·포트·프로토콜도 확인한다.
- (다-4) 인터넷에서 회사 내부망의 웹 서버에 접속하게 하려면 정적 NAT 과 동적 NAT 가운데 어느 방식이 맞는지 이유와 함께 설명하세요.
  - 답: 외부 요청을 항상 같은 웹 서버로 보내야 하므로 정적 NAT다. 포트 포워딩(정적 PAT)도 가능하며 방화벽 허용이 필요하다.

### 이 교시에 새로 안 것

- 사설 IP는 세 범위로 판단하며 `172.20.5.6`과 `172.32.5.6`은 분류가 다르다. 동적 NAT의 주소 배정과 PAT의 포트 구분은 별개이고 PC 추적에는 시각·변환 기록이 필요하다.

| 이전 이해 요약 | 확인 후 이해 |
|---|---|
| 십진수 10을 `00000010`으로 표시 | `10`은 `1010`, 8자리 표기는 `00001010`이다. `00000010`은 십진수 2다. |
| `2**8 = 255` | 경우의 수는 256개이고, 0부터 세므로 최댓값이 255다. |
| 사람마다 IP가 최소 3개라는 기준으로 주소 부족 설명 | 고정된 수가 아니라 인터넷 장비 증가와 한정된 공인 주소 수가 핵심이다. |
| 포트 번호만 알면 내부 PC를 특정할 수 있음 | 시각과 NAT/PAT 변환 기록, 연결 정보를 함께 확인해야 한다. |
| 웹 서버는 접속자가 많으니 동적 NAT 사용 | 접속자 수보다 서버 매핑을 고정해야 하는지가 선택 기준이다. |

## 3교시 · 서브넷 마스크 · CIDR

> 계산 기준은 기존 보고서·`warmup_2_1b.py`의 IPv4 `192.168.200.60`과 이 절에 이미 적힌 마스크 `255.255.0.0`이다. 코드 출력은 이 입력으로 직접 실행해 확인했다. 현재 실행 환경의 IP는 `192.168.100.107`로 달라, 두 환경의 관측값을 구분한다.

### 문제 3-1 · 내 서브넷 마스크 읽기

- (가-1) 내 서브넷 마스크 · CIDR · 주소 수 · 쓸 수 있는 수: 255.255.0.0, /16, 65,536개, 65,534개.
- (가-2) 내 IPv4 주소의 망 부분 · 장비 부분: `192.168.200.60`에서 앞 16비트인 `192.168`이 망 부분이고, 뒤 16비트인 `200.60`이 장비 부분이다. 네트워크 주소는 `192.168.0.0/16`이다.
- (나-1) 🔍 내 서브넷 마스크를 2진수로 펼쳤을 때 1 인 비트와 0 인 비트가 각각 주소의 어느 부분을 가리키는지, 1 이 8개인 마디의 수를 근거로 설명하세요.
  - 답: `11111111.11111111.00000000.00000000`에서 1은 망, 0은 장비 부분이다. 앞 두 마디는 같고 뒤 두 마디로 장비를 구분한다.
- (나-2) 내 마스크에서 CIDR 숫자가 어떤 계산으로 나오는지 1 이 8개인 마디의 수를 넣어 설명하세요.
  - 답: 연속된 1이 16개이므로 `/16`이다. 장비 비트 16개로 전체 `2**16 = 65,536`개, 네트워크·브로드캐스트를 빼면 65,534개다.
- (나-3) 같은 교실의 다른 PC 와 비교했을 때, 망 부분과 장비 부분 가운데 어느 쪽이 같고 어느 쪽이 다른가요? 그렇게 되는 이유를 「같은 망」의 뜻과 이어서 설명하세요.
  - 답: 같은 `/16` 서브넷이라면 망 부분 `192.168`은 같고 장비 부분은 중복되지 않아야 한다. 옆 PC를 실측한 결과는 아니다.
- (다-1) 내 마스크를 기준으로 `192.168.10.25` 와 `192.168.20.25` 가 같은 망인지 판정하고, 비교해야 하는 마디를 짚어 근거를 설명하세요.
  - 답: `/16`은 앞 두 마디를 비교하므로 두 주소 모두 네트워크 주소가 `192.168.0.0`이다. 세 번째 마디 10·20은 장비 부분이라 달라도 같은 망이다.
- (다-2) 같은 두 주소를 `/24` 마스크로 판정하면 결과가 어떻게 달라지나요?
  - 답: `/24`는 앞 세 마디를 비교하므로 `192.168.10.0/24`와 `192.168.20.0/24`는 다른 망이다. 같은 망 판정에는 마스크가 필요하다.
- (다-3) 마스크에 따라 판정이 달라진다는 사실이 통신 경로와 방화벽 규칙을 정할 때 왜 중요한지 설명하세요.
  - 답: 마스크를 잘못 읽으면 직접 전달과 게이트웨이 전달을 잘못 판단한다. 방화벽에서도 `/16`은 `/24`보다 넓게 허용하므로 CIDR과 네트워크 주소를 확인해야 한다.

### 문제 3-2 · 내 망 범위

- (가) 두 번째 파일(`warmup_3_2b.py`)의 내 주소/CIDR · 출력 세 줄: 입력 `192.168.200.60/16`.

```text
255.255.0.0
192.168.0.0
192.168.255.255
```

`warmup_3_2b.py`의 계산 결과다. 첫 파일의 수업 예시 `192.168.10.25/24`는 `255.255.255.0`, `192.168.10.0`, `192.168.10.255`를 출력했다.

- (나-1) 출력 세 줄이 각각 3.2 의 ① ~ ④ 가운데 어느 단계의 값인지: 첫째 줄은 ① 마스크, 둘째·셋째 줄은 ③ 망 범위의 네트워크 주소·브로드캐스트 주소다. ② 망·장비 부분의 구분을 적용한 결과이며, ④ 장비 주소 범위는 두 경계 사이인 `192.168.0.1~192.168.255.254`다.
- (나-2) 내 주소에서 `0` · `255` 로 바뀐 마디: 뒤쪽 세 번째·네 번째 마디 `200.60`이 네트워크 주소에서는 `0.0`, 브로드캐스트 주소에서는 `255.255`가 됐다.
- (나-3) 둘째 줄 값이 3.2 의 AND 연산으로 어떻게 나오는지 설명하세요.
  - 답: IP `11000000.10101000.11001000.00111100`과 마스크 `11111111.11111111.00000000.00000000`을 AND하면 앞 16비트만 남는다. 결과는 `11000000.10101000.00000000.00000000`, 즉 `192.168.0.0`이다.
- (나-4) 왜 그 마디만 바뀌고 나머지 마디는 그대로인지 망 부분과 장비 부분으로 설명하세요.
  - 답: `/16`의 앞 두 마디는 망 부분이라 유지한다. 뒤 두 마디를 모두 0으로 하면 네트워크, 모두 1로 하면 브로드캐스트 주소다.
- (다-1) `ipconfig` 의 내 기본 게이트웨이 주소가 둘째 줄과 셋째 줄 사이에 있는지(예 · 아니오): 현재 실행 환경에서 확인한 `192.168.1.1`을 비교하면 예 — `192.168.0.0`보다 크고 `192.168.255.255`보다 작다. 단, 이 값은 IP `192.168.100.107`인 실행 환경의 관측값이며, 보고서 IP `192.168.200.60`을 사용한 환경의 게이트웨이 실측값은 아직 확인되지 않았다.
- (다-2) 게이트웨이 주소가 이 범위 안에 있어야 하는 이유를 설명하세요.
  - 답: 일반 구성의 게이트웨이는 같은 서브넷에서 직접 도달 가능한 라우터 주소여야 한다. 그래야 ARP로 MAC을 알아내 다른 망으로 가는 프레임을 전달한다.
- (다-3) 게이트웨이 주소를 둘째 줄의 네트워크 주소나 셋째 줄의 브로드캐스트 주소로 잘못 설정하면 왜 문제가 되는지, 두 주소의 역할을 들어 설명하세요.
  - 답: `192.168.0.0`은 네트워크, `192.168.255.255`는 브로드캐스트 주소라 이 `/16`의 개별 게이트웨이에 배정할 수 없다.

### 이 교시에 새로 안 것

- 같은 망은 IP와 마스크를 함께 비교하고, CIDR은 연속된 1의 수·네트워크 주소는 AND 결과다. 내 `/16`은 `192.168.0.0~192.168.255.255`(장비용 `.0.1~.255.254`)이며 `strict=False`는 망 계산만 하고 실제 설정을 바꾸지 않는다.

## 4교시 · 서브네팅

> 정상 설정과 겹치는 설정의 계산 결과를 비교했다. 아래 값은 수업 예시망을 기준으로 한 계산이다.

### 문제 4-1 · 반으로 나누기 `/25`

- (가) 출력 두 줄:

```text
192.168.50.0/25
192.168.50.128/25
```
- (나-1) 4.1 표와 맞춰 쓴 블록마다의 범위:

| CIDR | 시작 IP | 끝 IP |
|---|---|---|
| /24 | 192.168.50.0 | 192.168.50.255 |
| /25 | 192.168.50.0 | 192.168.50.127 |
| /25 | 192.168.50.128 | 192.168.50.255 |
| /26 | 192.168.50.0 | 192.168.50.63 |
| /26 | 192.168.50.64 | 192.168.50.127 |
| /26 | 192.168.50.128 | 192.168.50.191 |

### 문제 5-1 · ARP 캐시에서 게이트웨이 찾기

- (가) 기본 게이트웨이 줄의 IP · MAC 주소 · `8.8.8.8` 줄이 있었나:
  - 기본 게이트웨이 IP: `192.168.1.1`

- (나) 🔍 방금 `8.8.8.8` 로 보냈는데도 ARP 캐시에는 내 망(학원 PC 는 앞 두 마디 `192.168`)의 장비만 있고 `8.8.8.8` 줄이 없는 이유를, 다른 망으로 보내는 프레임의 목적지 MAC 과 이어서 설명하세요.

- (다-3) ARP 가 MAC 주소를 알아낼 때 질문은 브로드캐스트로 보내고 답은 한 장비만 하는 이유를 설명하세요.
  - 답: ARP는 같은 링크에 특정 IP의 MAC을 브로드캐스트로 묻고, 일반적으로 그 IP를 가진 장비가 응답한다. `192.168.1.1`을 물으면 해당 게이트웨이가 자신의 MAC을 알려 준다.

| 운영팀 | 192.168.20.0/24 | 20 | 192.168.20.1 |
| 보안팀 | 192.168.30.0/24 | 30 | 192.168.30.1 |

- VLAN 하나에 서브넷 하나를 맞춘 이유를, 서로 다른 VLAN에 같은 서브넷을 주었을 때 PC와 스위치의 동작과 비교해 설명하세요.
  - 답: PC의 같은 망 판단과 VLAN 범위를 맞추기 위해서다. 다른 VLAN에 같은 서브넷을 쓰면 직접 ARP가 넘어가지 않아 실패하지만, 서로 다른 서브넷이면 게이트웨이를 거쳐 접근 통제할 수 있다.

### 2. 라우팅 경로 — 6-2

- 운영팀 PC `192.168.20.30` → 인터넷 `8.8.8.8`의 장비 경로와 라우팅 표의 줄:
  - 운영팀 PC → VLAN 20의 스위치 → 운영팀 게이트웨이 `192.168.20.1`인 회사 라우터 → 인터넷 쪽 라우터 → 이후 인터넷 경로 → `8.8.8.8`.
  - 회사 라우터에서 선택한 줄: `0.0.0.0/0 → 인터넷 쪽 라우터`.
- `192.168.30.5`와 `8.8.8.8`에서 다른 다음 홉을 고른 이유:
  - 답: `192.168.30.5`는 회사 `/24` 경로로 VLAN 30에, `8.8.8.8`은 기본 경로로 인터넷 라우터에 보낸다. 실제 선택은 일치하는 가장 긴 접두사가 우선이다.

### 3. 오늘 하루 정리

- 오늘 배운 것 가운데 가장 중요하다고 생각하는 것과 그 이유:
  - 답: IP만 보지 않고 마스크·VLAN·경로를 함께 확인해야 한다. PC는 다음 홉을 판단하고 스위치는 MAC으로 포트를 선택하므로 역할을 구분하면 장애·통제 지점을 찾기 쉽다.
