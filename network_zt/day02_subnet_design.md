## 2교시 · IP 주소 · 사설과 공인

> IP 주소는 실습 당시 기록한 값이다.

### 문제 2-1 · 내 IP 를 2진수로

- (가) 두 번째 파일(`warmup_2_1b.py`, 내 IPv4 주소)의 출력 네 줄:

```text
192 11000000
168 10101000
200 11001000
60 00111100
```
- (나-1) `format(number, "08b")` 가 마디 하나의 10진수를 어떤 형태의 글자로 바꾸는지, 내 출력 한 줄을 예로 들어 설명하세요.
  - 답: 정수를 이진수 문자열로 바꾸고, 8자리보다 짧으면 앞에 0을 채운다. 내 출력에서 60은 이진수 111100이므로 00111100으로 표시된다. IPv4 마디는 0~255여서 이 형식으로 8자리로 나타낼 수 있다.
- (나-2) `"08b"` 에서 `08` 을 빼고 `"b"` 만 쓰면 `10` 은 어떻게 출력되나요?
  - 답: `format(10, "b")`의 출력은 `1010`이다. `08`을 빼면 앞에 0을 채워 8자리로 맞추지 않는다. `"08b"`로 표시하면 `00001010`이다.
- (나-3) 마디마다 8자리로 맞춰 써야 하는 이유를 설명하세요.
  - 답: IPv4의 마디 하나는 8비트이므로 8자리로 쓰면 각 마디의 비트 경계를 정확히 볼 수 있다. 8비트가 나타내는 값은 `2**8 = 256`가지이고, 0부터 세므로 범위는 0~255이다. 최댓값은 `2**8 - 1 = 255`이다.
- (다-1) IPv4 주소가 32비트라는 것과 마디 하나가 `0` ~ `255` 사이의 값만 가진다는 것은 어떻게 이어지나요? 마디 수와 비트 수를 근거로 설명하세요.
  - 답: IPv4는 8비트짜리 마디 네 개로 구성되므로 8 × 4 = 32비트이다. 각 마디는 256가지 값, 즉 십진수 0~255를 나타낸다. 내 주소 192.168.200.60도 네 마디의 8비트 값을 합친 32비트 주소이다.
- (다-2) 32비트로 만들 수 있는 주소의 개수: 2**32 = 4,294,967,296개
- (다-3) 그 개수가 나오는 계산 과정을, 비트 한 자리에 들어갈 수 있는 값의 가짓수와 자리 수를 넣어 단계별로 설명하세요.
  - 답: 비트 한 자리에는 0과 1의 두 가지 값이 들어갈 수 있다. 두 자리의 조합은 2 × 2 = 4가지이고, 세 자리는 2 × 2 × 2 = 8가지이다. 같은 방식으로 32자리에서는 2를 32번 곱하므로 2**32 = 4,294,967,296개가 나온다. 2 × 32로 계산하는 것은 아니다.
- (다-4) 이 수의 한계가 사설 IP 와 NAT 를 쓰게 된 것과 어떻게 이어지는지 설명하세요.
  - 답: IPv4의 전체 조합은 약 43억 개이지만 예약된 용도도 있어 전부 공인 주소로 배정할 수는 없다. 장비 증가로 공인 IPv4가 부족해지면서 내부망의 사설 IP를 NAT로 변환해 쓰게 됐다. 특히 PAT는 여러 장비가 공인 IP 하나를 공유하도록 해 필요한 공인 IP 수를 줄인다.

### 문제 2-2 · 내 주소는 사설일까 — 인터넷이 보는 내 주소

- (가) `ipconfig` 의 내 IPv4 주소 · `curl` 로 본 공인 IP: 192.168.200.60, 1.245.252.171
- (나-1) 🔍 내 IPv4 주소는 2.2 표의 어느 범위에 들어가며, 그래서 사설과 공인 가운데 무엇인가요? 범위의 시작 주소와 끝 주소를 근거로 판정하세요.
  - 답: 내 주소 192.168.200.60은 사설 범위 192.168.0.0~192.168.255.255 안에 들어간다. 따라서 사설 IP이다. 내부망에서 사용하는 주소이며 인터넷에 직접 배정하는 공인 주소와 구분한다.
- (나-2) `curl` 로 본 주소는 사설과 공인 가운데 무엇인가요? 2.2 표의 세 범위와 맞춰 본 근거를 들어 설명하세요.
  - 답: 기록한 1.245.252.171은 10.0.0.0~10.255.255.255, 172.16.0.0~172.31.255.255, 192.168.0.0~192.168.255.255 중 어느 범위에도 속하지 않는다. 이번 실습에서 인터넷이 보는 출발지 주소이므로 공인 IP로 판정한다. 일반적으로 사설 범위 밖에는 예약·특수 주소도 있으므로 사설이 아니라는 이유만으로 모든 주소를 공인 IP라고 단정하지는 않는다.
- (나-3) 관제 로그의 출발지 주소가 `172.20.5.6` 과 `172.32.5.6` 이라면, 각각 내부망 장비와 외부 주소 가운데 무엇으로 먼저 분류해야 하나요? 2.2 표를 근거로 설명하세요.
  - 답: 172.20.5.6은 사설 범위 172.16.0.0~172.31.255.255 안에 있으므로 수업 기준에서는 내부망 장비로 먼저 분류한다. 172.32.5.6은 둘째 마디가 32로 범위를 벗어나므로 공인 IP, 즉 외부 주소로 먼저 분류한다. 172로 시작한다고 모두 사설 IP인 것은 아니며 실제 장비 소속은 회사의 주소 배정 정보도 함께 확인해야 한다.
- (다-1) 외부 서버 로그에 남은 출발지 IP 만으로는 내부망의 어느 PC 인지 특정할 수 없는 이유를 NAT 의 동작으로 설명하세요.
  - 답: NAT는 내부 PC의 사설 출발지 주소를 공인 주소로 변환하므로 외부 서버에는 변환된 주소가 남는다. PAT에서는 여러 PC가 같은 공인 IP를 공유하고, 동적 NAT에서도 같은 공인 IP가 시간에 따라 다른 PC에 배정될 수 있다. 따라서 출발지 IP만으로는 일반적으로 내부 PC를 특정할 수 없고 해당 시각의 변환 기록이 필요하다. 고정된 정적 NAT라면 매핑 설정을 확인해 내부 주소와 연결할 수 있다.
- (다-2) 정적 NAT 과 동적 NAT 은 사설 IP 와 공인 IP 를 연결하는 방식이 어떻게 다른가요?
  - 답: 정적 NAT는 사설 IP 하나와 공인 IP 하나를 고정된 1:1 관계로 연결한다. 동적 NAT는 공인 IP 풀에서 사용 가능한 주소를 통신이 필요할 때 배정한다. 동적 NAT도 매핑이 유지되는 동안은 1:1이지만 매핑 해제 뒤 같은 공인 IP를 다른 PC가 사용할 수 있다. 여러 PC가 공인 IP 하나를 동시에 공유하며 포트로 구별하는 방식은 PAT이다.
- (다-3) 사원 PC 여러 대가 인터넷을 쓸 때는 동적 NAT 을 쓰는 이유는 무엇인가요? 동적 NAT 환경에서 외부 로그의 공인 IP 로 PC 를 특정하려면 무엇을 함께 봐야 하는지와 이어서 설명하세요.
  - 답: 사원 PC는 보통 인터넷으로 접속하는 쪽이므로 공인 주소를 고정 배정할 필요가 없다. 동적 NAT는 공인 IP 풀에서 주소를 배정하고 매핑 해제 후 재사용하지만, 동시 사용 수는 풀 크기에 제한된다. 내부 PC를 추적하려면 통신 시각과 NAT 변환 기록을 확인하고, PAT라면 IP·포트·TCP/UDP 등 연결 정보도 함께 봐야 한다.
- (다-4) 인터넷에서 회사 내부망의 웹 서버에 접속하게 하려면 정적 NAT 과 동적 NAT 가운데 어느 방식이 맞는지 이유와 함께 설명하세요.
  - 답: 두 방식 중에서는 정적 NAT가 맞다. 공인 주소를 내부 웹 서버의 사설 주소에 고정 연결해야 외부 요청이 항상 같은 서버로 전달되기 때문이다. 웹 서비스 포트만 고정 연결하는 포트 포워딩(정적 PAT)도 가능하며, 방화벽 허용 설정을 함께 확인해야 한다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것:
  - 사설 IP는 세 범위로 판정한다. `172.20.5.6`과 `172.32.5.6`은 둘째 마디 때문에 분류가 달라진다.
  - 동적 NAT의 주소 배정과 PAT의 포트 구분은 다르다. 내부 PC 추적에는 통신 시각과 변환 기록이 필요하다.

| 이전 이해 요약 | 확인 후 이해 |
|---|---|
| 십진수 10을 `00000010`으로 표시 | `10`은 `1010`, 8자리 표기는 `00001010`이다. `00000010`은 십진수 2다. |
| `2**8 = 255` | 경우의 수는 256개이고, 0부터 세므로 최댓값이 255다. |
| 사람마다 IP가 최소 3개라는 기준으로 주소 부족 설명 | 고정된 수가 아니라 인터넷 장비 증가와 한정된 공인 주소 수가 핵심이다. |
| 포트 번호만 알면 내부 PC를 특정할 수 있음 | 시각과 NAT/PAT 변환 기록, 연결 정보를 함께 확인해야 한다. |
| 웹 서버는 접속자가 많으니 동적 NAT 사용 | 접속자 수보다 서버 매핑을 고정해야 하는지가 선택 기준이다. |

## 3교시 · 서브넷 마스크 · CIDR

> 계산 기준은 기존 보고서·`warmup_2_1b.py`의 IPv4 `192.168.200.60`과 이 절에 이미 적힌 마스크 `255.255.0.0`이다. 코드 출력은 이 입력으로 직접 실행해 확인했다. 현재 실행 환경의 IP는 `192.168.100.107`로 달라, 두 환경의 관측값을 구분한다.

### 문제 3-1 · 내 서브넷 마스크 읽기

- (가-1) 내 서브넷 마스크 · CIDR · 주소 수 · 쓸 수 있는 수: 255.255.0.0, /16, 65,536개, 65,534개.
- (가-2) 내 IPv4 주소의 망 부분 · 장비 부분: `192.168.200.60`에서 앞 16비트인 `192.168`이 망 부분이고, 뒤 16비트인 `200.60`이 장비 부분이다. 네트워크 주소는 `192.168.0.0/16`이다.
- (나-1) 🔍 내 서브넷 마스크를 2진수로 펼쳤을 때 1 인 비트와 0 인 비트가 각각 주소의 어느 부분을 가리키는지, 1 이 8개인 마디의 수를 근거로 설명하세요.
  - 답: 마스크는 `11111111.11111111.00000000.00000000`이다. 1인 비트는 망 부분, 0인 비트는 장비 부분을 가리킨다. 1이 8개인 마디가 두 개이므로 앞 두 마디가 같은 망을 나타내고, 뒤 두 마디로 그 망 안의 장비를 구분한다.
- (나-2) 내 마스크에서 CIDR 숫자가 어떤 계산으로 나오는지 1 이 8개인 마디의 수를 넣어 설명하세요.
  - 답: CIDR 숫자는 마스크의 앞에서 연속된 1의 개수다. 내 마스크는 1이 8개인 마디가 두 개이므로 8 + 8 = 16, 즉 `/16`이다. 전체 32비트 중 장비 부분은 16비트여서 주소 수는 2**16 = 65,536개이며, 일반적인 이 서브넷에서 네트워크·브로드캐스트 주소를 빼면 65,534개를 장비에 사용할 수 있다.
- (나-3) 같은 교실의 다른 PC 와 비교했을 때, 망 부분과 장비 부분 가운데 어느 쪽이 같고 어느 쪽이 다른가요? 그렇게 되는 이유를 「같은 망」의 뜻과 이어서 설명하세요.
  - 답: 같은 `/16` 서브넷에 속하는 다른 PC라면 망 부분 `192.168`은 같고 장비 부분은 달라야 한다. 같은 망이라는 것은 마스크를 적용해 얻은 네트워크 주소가 같다는 뜻이기 때문이다. 다만 옆 PC의 실제 주소를 이번에 확인한 것은 아니므로, 이는 같은 서브넷이라는 조건에서의 설명이다.
- (다-1) 내 마스크를 기준으로 `192.168.10.25` 와 `192.168.20.25` 가 같은 망인지 판정하고, 비교해야 하는 마디를 짚어 근거를 설명하세요.
  - 답: `/16`에서는 앞 두 마디 `192.168`을 비교하므로 같은 망이다. 두 주소 모두 `255.255.0.0`과 AND하면 네트워크 주소가 `192.168.0.0`이다. 세 번째 마디 10과 20은 이 마스크에서 장비 부분이므로 달라도 같은 망일 수 있다.
- (다-2) 같은 두 주소를 `/24` 마스크로 판정하면 결과가 어떻게 달라지나요?
  - 답: `/24`에서는 앞 세 마디가 망 부분이라 `192.168.10`과 `192.168.20`이 달라 서로 다른 망이다. 네트워크 주소도 각각 `192.168.10.0/24`, `192.168.20.0/24`로 나온다. 따라서 IP 주소만 보지 말고 마스크까지 함께 확인해야 한다.
- (다-3) 마스크에 따라 판정이 달라진다는 사실이 통신 경로와 방화벽 규칙을 정할 때 왜 중요한지 설명하세요.
  - 답: 일반적인 구성에서는 같은 서브넷의 목적지에 직접 전달하고 다른 서브넷으로는 라우터를 통해 전달하므로, 마스크를 잘못 읽으면 필요한 통신 경로를 잘못 판단한다. 방화벽에서 `/16`을 허용하면 `/24`보다 훨씬 넓은 주소 범위를 허용한다. 경로와 허용 범위를 정확히 정하려면 네트워크 주소와 CIDR을 함께 확인해야 한다.

### 문제 3-2 · 내 망 범위

- (가) 두 번째 파일(`warmup_3_2b.py`)의 내 주소/CIDR · 출력 세 줄: 입력 `192.168.200.60/16`.

```text
255.255.0.0
192.168.0.0
192.168.255.255
```

`warmup_3_2b.py`의 계산 결과다. 첫 파일의 수업 예시 `192.168.10.25/24`는 `255.255.255.0`, `192.168.10.0`, `192.168.10.255`를 출력했다.

- (나-1) 출력 세 줄이 각각 3.2 의 ① ~ ④ 가운데 어느 단계의 값인지: 첫째 줄은 ① 마스크, 둘째·셋째 줄은 ③ 망 범위의 네트워크 주소·브로드캐스트 주소다. ② 망·장비 부분의 구분을 적용한 결과이며, ④ 장비 주소 범위는 두 경계 사이인 `192.168.0.1~192.168.255.254`다.
- (나-2) 내 주소에서 `0` · `255` 로 바뀐 마디: 뒤쪽 세 번째·네 번째 마디 `200.60`이 네트워크 주소에서는 `0.0`, 브로드캐스트 주소에서는 `255.255`가 됐다.
- (나-3) 둘째 줄 값이 3.2 의 AND 연산으로 어떻게 나오는지 설명하세요.
  - 답: 내 IP는 `11000000.10101000.11001000.00111100`이고, 마스크는 `11111111.11111111.00000000.00000000`이다. 같은 비트끼리 AND하면 앞 16비트는 그대로 남고 뒤 16비트는 모두 0이 된다. 결과 `11000000.10101000.00000000.00000000`을 십진수로 바꾸면 `192.168.0.0`이다.
- (나-4) 왜 그 마디만 바뀌고 나머지 마디는 그대로인지 망 부분과 장비 부분으로 설명하세요.
  - 답: `/16`의 앞 두 마디는 망 부분이라 같은 망을 가리키는 값으로 유지한다. 뒤 두 마디는 장비 부분이므로 모두 0으로 두면 네트워크 주소, 모두 1로 두면 브로드캐스트 주소가 된다. 그래서 255인 마스크의 앞 두 마디는 그대로이고 0인 뒤 두 마디만 바뀐다.
- (다-1) `ipconfig` 의 내 기본 게이트웨이 주소가 둘째 줄과 셋째 줄 사이에 있는지(예 · 아니오): 현재 실행 환경에서 확인한 `192.168.1.1`을 비교하면 예 — `192.168.0.0`보다 크고 `192.168.255.255`보다 작다. 단, 이 값은 IP `192.168.100.107`인 실행 환경의 관측값이며, 보고서 IP `192.168.200.60`을 사용한 환경의 게이트웨이 실측값은 아직 확인되지 않았다.
- (다-2) 게이트웨이 주소가 이 범위 안에 있어야 하는 이유를 설명하세요.
  - 답: 이 수업의 일반적인 구성에서 기본 게이트웨이는 내 PC가 같은 서브넷에서 직접 도달할 수 있는 다음 라우터다. 그래야 ARP로 게이트웨이의 MAC을 알아내고 다른 망으로 갈 프레임을 전달할 수 있다. 따라서 장비에 사용할 수 있는 같은 서브넷의 주소로 설정한다.
- (다-3) 게이트웨이 주소를 둘째 줄의 네트워크 주소나 셋째 줄의 브로드캐스트 주소로 잘못 설정하면 왜 문제가 되는지, 두 주소의 역할을 들어 설명하세요.
  - 답: `192.168.0.0`은 이 망 자체를 나타내는 네트워크 주소이고, `192.168.255.255`는 서브넷 전체에 보내는 브로드캐스트 주소다. 이 `/16`에서 둘 다 개별 라우터의 인터페이스에 줄 일반 장비 주소가 아니다. 게이트웨이로 지정하면 정상적인 다음 라우터를 가리키지 못해 다른 망으로 전달하는 데 문제가 생긴다.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것:
  - 앞 세 마디가 다르면 무조건 다른 망인 것은 아니다. `/16`에서는 앞 두 마디를 비교하고, `/24`에서는 앞 세 마디를 비교한다.
  - CIDR은 마스크의 연속된 1의 개수이고, 네트워크 주소는 IP와 마스크의 AND 결과다.
  - 내 기록의 `/16` 망은 `192.168.0.0~192.168.255.255`이고 일반 장비 주소 범위는 `192.168.0.1~192.168.255.254`다.
  - `strict=False`는 장비 IP를 넣어도 그 주소가 속한 망을 계산하게 한다. 실제 IP 설정을 변경하는 옵션은 아니다.

## 5교시 · 스위치와 라우터

### 문제 5-1 · ARP 캐시에서 게이트웨이 찾기

- (가) 기본 게이트웨이 줄의 IP · MAC 주소 · `8.8.8.8` 줄이 있었나:
  - 기본 게이트웨이 IP: `192.168.1.1`
  - 기본 게이트웨이 MAC: `00-10-f3-a3-fc-96`
  - `8.8.8.8` 줄: 없음
- (나) 🔍 방금 `8.8.8.8` 로 보냈는데도 ARP 캐시에는 내 망(학원 PC 는 앞 두 마디 `192.168`)의 장비만 있고 `8.8.8.8` 줄이 없는 이유를, 다른 망으로 보내는 프레임의 목적지 MAC 과 이어서 설명하세요.
  - 답: `8.8.8.8`은 다른 망에 있으므로 내 PC는 먼저 게이트웨이로 전달한다. IP 패킷의 목적지는 `8.8.8.8`이지만, 처음 나가는 이더넷 프레임의 목적지 MAC은 게이트웨이의 `00-10-f3-a3-fc-96`이다. ARP로 찾는 것은 같은 링크의 다음 장비 MAC이므로, 표에는 게이트웨이 줄이 있고 `8.8.8.8` 줄은 없었다.

- (다-1) MAC 주소와 IP 주소는 각각 누가 정하나요?
  - 답: MAC 주소는 보통 NIC 제조사가 부여하고, IP 주소는 DHCP 서버가 자동으로 배정하거나 관리자가 수동으로 설정한다. MAC도 운영체제 설정이나 무작위 MAC 기능 등에 의해 바뀔 수 있다.

- (다-2) 패킷이 다른 망으로 건너갈 때 목적지 IP 주소와 MAC 주소가 바뀌는지 그대로인지 비교해 설명하세요.
  - 답: 일반적인 라우팅에서는 목적지 IP가 최종 목적지 주소로 유지된다. 라우터가 다음 이더넷 링크로 보낼 때는 새 프레임을 만들어, 출발지 MAC을 자신의 송신 인터페이스 MAC으로, 목적지 MAC을 다음 장비 MAC으로 설정한다. NAT는 주소 변환이 설정된 지점의 별도 동작이므로, 모든 망 경계에서 목적지 IP가 바뀌는 것은 아니다.

- (다-3) ARP 가 MAC 주소를 알아낼 때 질문은 브로드캐스트로 보내고 답은 한 장비만 하는 이유를 설명하세요.
  - 답: ARP는 “이 IP 주소를 가진 장비의 MAC이 무엇인가?”를 묻는 과정이다. 목적지 MAC을 모르므로 같은 링크에 브로드캐스트하고, 일반적으로 해당 IP를 가진 장비가 자신의 MAC을 응답한다. 예를 들어 `192.168.1.1`의 MAC을 물으면 그 IP를 가진 게이트웨이가 답하고, 다른 장비는 자기 IP에 대한 질문이 아니므로 응답하지 않는다.

**(다-2) 기존 답**

목적지 IP 주소는 공인IP에서 해당 망 안에서 NAT로 인해 사설IP로 바뀔 것이고, MAC 주소는 해당 내부 망으로 들어가서 ARP 조회 해볼 때까지 알 수 없다.

**(다-3) 기존 답**

ARP가 모든 장치에게 브로드캐스트하여 해당 MAC 주소랑 일치하는 장비만 응답하고 일치하지 않는 장비들은 해당 패킷을 폐기하기 때문이다.

</details>

  - 답: 두 코드의 표에는 `AA: 1`만 있다. 첫 파일의 목적지 `BB`는 표에 없어 플러딩하고, 두 번째 파일의 목적지 `AA`는 표에 있어 값인 1번 포트로 전달한다고 출력한다. 실제 플러딩은 같은 VLAN에서 들어온 포트를 제외한 전달 가능한 포트로 프레임을 복사하는 것이다.

- (나-2) 둘째 출력에 `AA` 가 아니라 숫자가 나온 이유를 딕셔너리의 키와 값으로 설명하세요.
  - 답: `AA`는 딕셔너리의 키이고 1은 그 키에 대응하는 값이다. 코드는 `mac_table[dest]`로 값을 꺼내므로 MAC 이름 `AA` 대신 포트 번호 1을 출력한다.

  - 답: MAC 주소 `AA`에 대응하는 스위치의 물리적 1번 포트이다. HTTP의 80처럼 TCP·UDP의 서비스 포트 번호를 뜻하는 것은 아니다.

- (다-1) 플러딩은 어떤 조건에서 일어나나요?
  - 답: 받은 프레임의 목적지 MAC이 MAC 주소 표에 없을 때 플러딩한다. 이 문제는 목적지를 모르는 유니캐스트의 경우이며, 브로드캐스트도 같은 VLAN 안으로 전달된다.

- (다-2) 5.3 의 예처럼 처음에는 플러딩하던 스위치가 그다음부터 한 포트로만 보내게 되는 과정을 설명하세요.
  - 답: 스위치는 프레임의 출발지 MAC과 들어온 포트를 저장해 학습한다. 예시에서 `CC → DD`가 2번으로 오면 `CC:2`를 배우지만 DD는 몰라 1·3·4번으로 플러딩한다. 이후 `DD → CC`가 4번으로 오면 `DD:4`를 배우고 CC가 있는 2번으로만 전달하며, 다음부터 DD로 가는 프레임은 4번으로 전달할 수 있다.

  - 다음 장비의 MAC이 캐시에 있으면 재사용하고, 없으면 ARP로 알아낼 수 있다.
  - 스위치는 출발지 MAC으로 학습하고 목적지 MAC으로 전달 포트를 선택한다. 이때의 포트는 TCP·UDP의 포트와 다른 물리적 연결 포트이다.

|---|---|
| IP는 모두 DHCP가 정함 | DHCP 자동 배정과 관리자 수동 설정이 모두 가능하다. |

- (다-4) 이때 같은 망 통신과 인터넷 통신이 각각 어떻게 되는지 이유와 함께 설명하세요.

### 이 교시에 새로 안 것

- 이 교시에서 새로 알게 된 것:
  - 기본 경로는 다른 경로가 모두 통과했다는 뜻이 아니라, 목적지에 맞는 더 구체적인 경로가 없을 때 사용하는 경로이다.
  - `found`는 회사 망의 일치 여부를 기록하는 변수다. `False`가 남으면 실습 코드의 기본 경로 안내가 실행된다.
  - 코드는 회사 망 세 줄을 순서대로 비교하지만, 실제 라우팅에서는 목적지에 일치하는 가장 긴 접두사 경로를 우선 선택한다.
  - VLAN은 브로드캐스트 범위를 나누고, 라우터·L3 스위치의 접근 통제는 VLAN 간 통신을 제한한다. 분리와 접근 통제를 함께 적용해야 한다.
  - 기본 경로가 없어도 직접 연결 경로가 남아 있으면 같은 망 통신은 가능하다. 모든 통신이 기본 게이트웨이를 거치는 것은 아니다.

### 1. 부서마다 망 · VLAN · 게이트웨이 — 5.2 · 6.1 · 6.3

| 부서 | 서브넷 | VLAN | 게이트웨이 |

  - 답: 주소만 보지 않고 마스크·VLAN·경로를 함께 확인해야 한다는 점이 중요하다. 같은 IP라도 마스크에 따라 직접 전달할지 게이트웨이를 거칠지 달라지고, VLAN은 실제 브로드캐스트 범위를 나눈다. PC는 망과 다음 홉을 판단하고 스위치는 MAC으로 포트를 선택한다는 역할 차이를 구분하면 장애 원인과 접근 통제 지점을 더 정확히 설명할 수 있다.
